# Offerbiu 视觉设计调研与改版方案

## 设计方向

把 Offerbiu 做成一本可操作的「校招手册」。首页有出版物的节奏，用版次、标题和栏线建立识别度。工作台像手册的索引和记录页，用稳定的对齐关系让人快速扫到岗位、地点、截止时间和下一步。

保留「让每一次投递，都有下一步」和现有品牌蓝。把首屏的轨道、浮动简历和装饰窗合成一个能读清的产品预览。用现有界面、可核验的岗位内容和少量角色反馈撑起视觉，撤掉泛用的玻璃卡片、背景光斑和循环漂浮。

## 首页与工作台

### 首页

- 顶部只保留品牌、岗位库、简历工作室和进入工作台。Hero 左侧用「2027 届 / 校招手册」眉题和原有两行主标题。主操作为「浏览校招岗位」，次操作为「进入工作台」。
- 桌面端右侧只放一块预览，用现有岗位、简历和投递界面的组件表现同一条求职路径。三段标签为「查岗位 / 准备简历 / 跟进进度」。使用演示记录时，直接标注「界面示例」。手机先显示标题和操作，再显示一块精简预览。
- 下方以细栏线开启「近期核验」。只有带实际核验时间的官方岗位才放进这一区，时间按已有数据展示。沿用企业官方招聘渠道和西北大学就业信息的来源边界，具体岗位直达投递链接。
- 现有企鹅可以在「保存成功」时点头一次，也可以作为空状态的一处小插图。滚动到对应段落时同步预览页签，保持页面自然滚动。页签也可点击和键盘切换，约 180–220 ms 完成，系统开启减少动态效果时直接切换。

### 岗位库

- 把现在占据列表前方的企业快捷入口、行业选项和统计收进筛选层。第一屏先给搜索、Base、岗位方向和第一条结果，活跃条件与结果数贴近列表。
- 桌面采用左侧列表、右侧详情。每条先给岗位名，其次是企业、Base、截止日期和来源，保留一个轻量的「去官网投递 ↗」。职责、要求和已有匹配结果归到详情。移动端点入详情后，返回保留查询和滚动位置。
- 官方未公布地点或时间时直接显示「未公布」。核验时间与截止日期分别标记，历史条目有明确状态。

### 我的投递与简历

- 总览首块改为「下一步」，按时间分组显示准备简历、笔试、面试或跟进任务。「我的投递」维持状态筛选和时间线，列表优先显示岗位、当前状态、最近一次更新和下一步。
- 简历页先统一编辑工具栏、保存状态和 A4 预览的视觉样式。润色建议出现在所选段落附近，采纳由用户确认。打印样式和模板版式独立于工作台改版。

## 视觉参数与交付顺序

- **颜色**　页面暖白 `#F7F6F2`、内容面白 `#FFFFFF`、正文墨黑 `#191E29`、辅助文字 `#5D6573`、分隔线 `#DFE2E7`。现有 `#365CF5` 用于主按钮、链接、焦点和选中状态。状态同时用文字表达。
- **排版**　正文用系统中文黑体。首页标题桌面 56–64 px，手机 34–38 px，工具页标题 26–32 px，表单和岗位正文 14–16 px。用 8 / 16 / 24 / 32 px 的间距，日期数字对齐。列表主要靠细线分组，大面板只留少量圆角。
- **第一轮**　先做首页首屏和岗位库一屏，按 1440 px 桌面与 390 px 手机各看一版。视觉验收关注首屏主操作、长岗位名、多 Base、日期未公布、筛选后无结果和减少动态效果的表现。岗位结果中一次点击可去官方投递页，返回详情前的筛选和位置可恢复。
- **第二轮**　把通过评审的排版与控件应用到总览、我的投递和日程，再统一简历编辑与模板页。优先复用共享样式、组件和已有数据。

实现采用共享配色和原生 CSS。首页核验区读取岗位已有的链接检查记录，标题旁使用小型 SVG 企鹅，目录旁复用原有人物动画。岗位详情在宽屏显示为阅读栏，窄屏使用原生弹窗以保留筛选与列表位置。
