# Offerbiu 下一阶段功能开发计划

- 编写日期：2026-11-09。
- 状态：实施中。实际完成范围和验证证据见[开发验收记录](下一阶段开发验收记录.md)。
- 范围依据：用户选择上一轮功能分析中的第 1、2、4、5 项。
- 计划目标：接入私人岗位，完善招聘过程与提醒，提供岗位订阅，降低简历导入与交付成本。
- 排期口径：按一名熟悉当前项目的开发者估算，包含对应阶段测试，不作为交付承诺。来源适配与文档解析需在 M0 用样例校准工作量。

## 1. 本轮范围与现有基础

| 用户选择 | 本轮功能 | 已有基础 | 本轮新增结果 |
| --- | --- | --- | --- |
| 1 | 私人岗位导入 | 官方岗位库；已有岗位可补充私人 JD；岗位评估、材料和投递留档 | 外部找到的岗位可独立保存，并进入完整求职工作流 |
| 2 | 提醒与招聘轮次管理 | 投递状态、事件时间线、关联待办、站内日历 | 招聘轮次、结束原因、通知导入、时间冲突提示、提醒与日历导出 |
| 4 | 岗位订阅与变化提醒 | 岗位筛选、来源快照、状态与正文质量标注 | 保存筛选、关注企业、增量更新、新增岗位与内容变化提醒 |
| 5 | 简历导入与投递前检查 | 结构化编辑、JSON 导入导出、HTML 导出、浏览器打印 PDF | PDF/DOCX 导入确认、中文 DOCX 导出、内容检查与排版预检 |

本轮围绕以上四项推进。面试模拟与复盘、Offer 比较、求职效果统计、岗位横向决策不进入本轮。第 2 项中的“面试轮次和记录”属于招聘流程管理，不扩展为面试训练产品。

当前功能判断来自仓库源码和操作指南的静态核对，未在本次规划中重新运行应用或验证模型、岗位网站、文件转换效果。历史验收结果不作为本轮新增功能已通过的证据。

## 2. 推进顺序、里程碑与依赖

建议按以下顺序交付，每阶段形成可实际使用的增量。

| 阶段 | 工作内容 | 核心交付 | 前置依赖 | 初估工作日 |
| --- | --- | --- | --- | --- |
| M0 | 现状基线、交互路径和样例验证 | 范围清单、迁移方案、通知能力样例、文件解析样例、首批来源清单 | 无 | 1–2 |
| M1 | 私人岗位导入与全流程接通 | 导入、查重、私人岗位管理、评估、材料、实际投递留档 | M0 | 4–6 |
| M2 | 招聘轮次、提醒与日历 | 轮次管理、结束原因、通知粘贴、时间冲突、提醒、ICS 导出 | M1 | 4–6 |
| M3 | 岗位订阅与更新 | 保存筛选、企业关注、首批来源更新、变更比较和订阅消息 | M1；提醒展示复用 M2 | 4–6 |
| M4 | 已有简历导入 | 文本型 PDF、DOCX 提取、逐项核对、创建新简历、底稿衔接 | M0；集成验收使用 M1 | 4–6 |
| M5 | DOCX 导出与投递前检查 | 中文 Word 模板、内容检查、排版预检、目标岗位缺失表达提示 | M4；岗位检查使用 M1 | 3–5 |
| M6 | 整体验收与交付 | 场景验收、迁移与回归记录、更新操作指南和范围说明 | M1–M5 | 2–3 |

基础估算合计 **22–34 个工作日**。考虑来源适配、中文文档兼容问题与修正，建议留出约 20%–30% 缓冲，按约 **6–9 周**安排。M0 结束后根据样例结果重估；排期不默认包含所有招聘网站的自动适配或任意复杂文档的版式复原。

M4 的解析样例研究可以提前做，正式接入仍沿用表中顺序。M3 依赖真实的数据更新，单纯保存筛选条件不能算完成岗位订阅。

## 3. M0：建立可实施的基线

### 开发任务

1. 盘点现有账号、岗位、投递、评估、材料、简历历史与待办接口，记录旧功能行为。
2. 在独立测试数据库上验证现有核心流程，保留成功项、失败项和待验证项。
3. 定义私人岗位与公共岗位的引用方式，检查现有外键、关联查询、唯一约束、缓存与快照兼容。
4. 约定轮次、结束原因、通知状态、日期与时区规则；默认显示 Asia/Shanghai。
5. 验证浏览器通知与 ICS 在目标设备上的实际效果，记录网页关闭或服务停止时的行为。
6. 准备脱敏或合成简历样例：中文单栏、双栏、表格、混合中英文、跨页、图片型 PDF、损坏文件。
7. 从现有白名单内选择 2–3 个可维护的官方来源作为首批刷新适配对象，固定岗位身份和变更比较样例。
8. 明确 PDF/DOCX 解析与导出的依赖、体积/页数限制、安装和启动方式；在这里确定库和版本，实施时核对官方文档。

### 完成标准

- 四项功能均有页面入口、完整用户路径和失败处理说明。
- 数据迁移在副本上可重跑，旧记录可查询，个人数据不进入公共岗位库。
- 获得通知与文件解析的实际样例结果，不能只凭库的说明承诺兼容。
- 现有未提交改动作为基线的一部分记录，不覆盖或回退用户其他工作。

## 4. M1：私人岗位导入与全流程接通

### 用户路径

“新增私人岗位” → 粘贴链接/正文或手动填写 → 查看提取结果 → 核对与查重 → 保存到本人岗位 → 评估 → 准备材料 → 投递 → 留档。

### 功能拆分

| 编号 | 功能 | 实施内容 |
| --- | --- | --- |
| J-01 | 手动创建 | 公司、岗位名、城市、招聘届别、职责、要求、截止日期、来源渠道、来源链接、投递链接、备注；未知字段允许留空 |
| J-02 | 正文导入 | 粘贴招聘正文，提取为待确认字段；保留原文，缺失内容不补造 |
| J-03 | 链接导入 | 对可直接读取的公开页面尝试提取；登录页、动态页或失败页面允许改为粘贴正文；只保存链接也可建档，正文不足时明确限制评估 |
| J-04 | 查重与来源管理 | 相同来源岗位 ID 或规范化 URL 给出强重复提示；公司、岗位名和地点相似仅提示疑似重复；由用户决定复用、补充来源或独立保存 |
| J-05 | 私人岗位管理 | 搜索、编辑、归档；保留版本、来源类型与录入时间；只对所属账号可见 |
| J-06 | 工作流接通 | 公共和私人岗位都可进入评估、批次选择、材料生成、简历采纳、投递状态与留档 |

### 关键规则

- 公共岗位准入规则继续适用于公共目录；私人岗位单独存储与授权，不以伪造官方来源字段实现接入。
- 本人确认录入内容不等于官方已核验招聘状态。私人正文中的要求保留来源说明，自动提取的硬条件默认待核实。
- 统一岗位引用需要覆盖投递、评估、材料一致性检查、AI 润色目标、留档和个人导出，不能只改岗位列表。
- 评估缓存包含岗位类型、稳定身份、正文版本和本人资料版本；内容修改后旧结果标为历史来源。
- 重复来源可以挂到同一岗位，但不会自动合并两个已有投递及其材料、轮次、留档。
- 默认归档已有业务记录的岗位，历史 JD 与实际投递快照仍可独立读取。永久删除需明确关联记录处理范围。
- 远程页面提取不携带用户招聘平台凭据；限制目标地址、重定向、响应大小与超时，避免读取本机或内网地址。

### 验收标准

1. 手动、正文、可读取链接三条路径均可创建私人岗位；链接读取失败仍能完成手动录入。
2. 两个账号不能互读、互改或将对方私人岗位用于评估和留档。
3. 私人岗位完成“评估 → 材料复核 → 创建新简历 → 保存实际投递快照”，官方岗位原流程也通过。
4. 同一链接反复提交有重复提示；相似岗位不会被静默合并。
5. 修改或归档私人岗位后，历史评估有版本提示，已保存留档内容不变。

## 5. M2：招聘轮次、提醒与日历

### 功能拆分

| 编号 | 功能 | 实施内容 |
| --- | --- | --- |
| P-01 | 招聘轮次 | 每条投递可新增笔试、一面、二面、终面、HR 面及自定义轮次；记录顺序、时间范围、形式、地点/会议链接、联系人、备注与结果 |
| P-02 | 生命周期 | 轮次支持待安排、已安排、已完成、取消；改期保留事件记录；投递状态与轮次联动，但不自动将完成一轮解释为通过 |
| P-03 | 结束原因 | 对“已结束”增加被拒绝、主动放弃、岗位取消等原因；Offer 增加待决定、接受、拒绝结果；不引入 Offer 条件比较 |
| P-04 | 通知粘贴 | 粘贴邮件、短信或招聘通知正文，提取岗位、轮次、日期、时长、地点与链接；用户确认后建立安排 |
| P-05 | 时间检查 | 有起止时间时检查重叠；仅有开始时间时提示信息不足并允许补充时长；“明天”等相对日期需明确通知日期后才能转换 |
| P-06 | 提醒 | 为截止、笔试、面试、跟进配置提前量；支持默认 24 小时/1 小时及自定义；记录已提醒、已读、稍后提醒与取消 |
| P-07 | 日历导出 | 导出单条或选定安排为 ICS，带时区、稳定事件标识、更新序号、描述和提醒设置；无确切时间的任务保留在待安排清单 |
| P-08 | 跟进提示 | 用户可设定等待反馈天数，系统列出需关注事项；只形成待办，不自动联系招聘方 |

### 提醒的交付边界

- 站内消息保存到账号，用户重新进入时可以看到未读与错过事项。
- 浏览器通知在权限与运行条件满足时触发；网页未运行或本机服务停止时，不承诺浏览器继续推送。
- 希望关闭网页后仍收到提醒的用户，可将 ICS 导入系统日历，由该日历负责提醒；在实际测试过的日历客户端说明兼容范围。
- 下载 ICS 属于一次性导出，页面修改不等于外部日历自动同步。再次导出使用稳定标识，并提示目标客户端可能需要更新或移除旧事件。
- 运行恢复后按既定窗口补记错过事项，集中展示，避免连续弹出大量过期提醒。

### 完成与删除规则

- 一个轮次关联的待办与提醒具有稳定关系，重复保存、改期或接口重试不会重复创建。
- 改期后撤销旧提醒，按新时间重算；完成或取消轮次后停止后续提醒。
- 系统记录通知已发起与用户已读；两者不能等同于用户一定看到。
- 轮次明细与原投递总状态共同展示。手工设置状态、跳过轮次、取消轮次都有明确的事件记录。

### 验收标准

1. 同一投递可完整记录笔试、两轮面试、改期、取消和结束原因。
2. 时间冲突、缺失时区/年份、相对日期歧义均可被用户发现并修正。
3. 通知权限允许、拒绝、网页关闭、服务重启、错过提醒分别有实际验证记录。
4. 改期与重复请求不会产生重复安排；旧提醒不再触发。
5. 至少在一款实际可用的桌面日历和一款手机日历验证 ICS 的时间、中文、链接与提醒；未测客户端不宣称兼容。
6. 旧待办与投递时间线仍可使用；通知解析失败可以继续手动创建安排。

## 6. M3：岗位订阅与变化提醒

### 功能拆分

| 编号 | 功能 | 实施内容 |
| --- | --- | --- |
| S-01 | 保存筛选 | 保存关键词、企业、行业、方向、城市、企业性质、届别/批次等当前支持的条件；可命名、编辑、暂停和删除 |
| S-02 | 企业关注 | 在企业或岗位详情关注企业，以企业条件订阅复用同一套匹配逻辑 |
| S-03 | 新增岗位 | 订阅建立时记录基线；之后首次进入匹配范围的岗位进入消息清单，区分新收录与原岗位修改后开始匹配 |
| S-04 | 岗位变更 | 对收藏岗位的职责、条件、地点、截止时间和招聘状态做前后比较；突出变化字段与来源时间 |
| S-05 | 更新入口 | 展示来源覆盖、最近成功更新、失败状态；支持手动刷新，首批已适配来源在本机服务运行时按默认每日一次刷新 |
| S-06 | 消息中心 | 合并同次刷新中来自多个订阅的重复命中；支持未读、已读、跳转详情和关闭某条订阅提醒 |

### 数据更新必须同时完成

1. 复用既有采集和来源准入规则；首批接通 M0 确定的 2–3 个已有官方来源，随后按来源逐批扩大。
2. 建立稳定来源岗位 ID、成功刷新批次、字段快照及字段变化记录；不能以每次导入时间判断岗位是新增。
3. 引入运行中的增量导入入口，使新数据进入当前服务；不把“重新启动才读新文件”当作自动订阅完成。
4. 刷新成功才推进对应来源的成功基线；超时、解析失败或登录限制保留上次成功数据和失败提示。
5. 某岗位从一次结果中缺失，不直接判定停止招聘。只有明确关闭证据或确定截止日期到期才作为关闭通知。
6. 首次建订阅默认展示当前匹配结果，当前结果不全量计入“新机会”通知；用户可主动查看初始结果。
7. 同一来源批次重试、服务重启、多个相同订阅命中，都不能重复发送相同变更事件。
8. 未适配来源展示覆盖说明与最近采集时间；不承诺全目录实时更新。本机服务停机期间不刷新，恢复后检查是否应补跑一次。
9. 私人岗位的手工修改可以产生本人变化记录；自动网页监测仅对明确支持的读取方式开放，不监测微信群或登录后的平台消息。

### 验收标准

- 首批真实来源至少完成一次成功读取与导入，并记录样例、来源和时间；不能仅用模拟数据宣称采集可用。
- 受控快照覆盖新增岗位、要求改变、截止时间变化、重新匹配、明确关闭和重复导入，消息结果正确。
- 刷新失败不批量下架岗位，不清空个人收藏，也不推进成功基线。
- 暂停订阅后不产生新消息；恢复时按既定基线补充摘要，不逐条轰炸历史变化。
- 筛选页面结果与同条件订阅结果一致；企业关注复用相同规则。

## 7. M4：已有 PDF / Word 简历导入

### 用户路径

选择文件 → 本地服务提取文字 → 按模块核对 → 处理遗漏或重复 → 创建新简历 → 主动选择是否导入经历底稿。

### 功能拆分

| 编号 | 功能 | 实施内容 |
| --- | --- | --- |
| R-01 | 文件接收 | 首版支持含文本层的 PDF 和 DOCX；校验实际文件类型、体积和页数；损坏、加密、不支持格式有明确反馈 |
| R-02 | 内容提取 | 提取基本信息、教育、实习、项目、技能、荣誉；保留原始提取文本和可获取的页码/段落位置 |
| R-03 | 核对页面 | 并排查看原始内容与结构化结果；逐项编辑、删除、补充或重分模块；无法归类的文字进入“待整理”，不静默丢弃 |
| R-04 | 确认保存 | 默认创建新简历；若用户选择导入现有简历，显示字段差异后逐项选择，不直接覆盖 |
| R-05 | 底稿衔接 | 简历导入成功后可以预览添加到真实经历底稿；沿用逐条确认流程，导入内容不会自动成为已确认事实 |
| R-06 | 失败回退 | 文件无法解析时可复制文字或手动填写；已有 JSON 导入继续可用 |

### 首版支持边界

- Word 首版指 DOCX。旧版 DOC 提示另存为 DOCX 后导入。
- 图片型/扫描 PDF 明确提示没有可用文字层；OCR 作为后续扩展，不以空结果冒充导入成功。
- 首版目标是可核对的内容迁移，导入后套用站内模板；不承诺复原任意原文件的精确版式。
- 头像、作品图首版由用户重新选择上传，不自动猜测文件中每张图片的用途。
- 原始文件默认仅作临时解析用途，结束或失败后清理；保存内容和个人导出范围在界面说明。
- 文本提取与手动核对应独立可用。若增加 AI 辅助分段，只在用户主动选择后发送已展示的必要文字，失败时仍能继续手动整理。

### 验收标准

1. 至少 12 份脱敏/合成样例覆盖单栏、双栏、表格、中英文混排、跨页和异常输入。
2. 对照原文人工核验姓名、联系方式、机构、角色、日期和成果数字；不得新增文件中没有的事实。
3. 关键字段错位或缺失可以在确认页发现并修改；记录每类样例的缺失和错误，不只报告“文件能打开”。
4. 取消导入不创建简历；重复确认不重复创建；源简历、历史版本和底稿不被静默覆盖。
5. 扫描件、损坏文件、超限文件返回清楚的原因与可行下一步，不影响正常编辑。

## 8. M5：中文 DOCX 导出与投递前检查

### 中文 DOCX 导出

- 增加“导出 Word”入口，首版提供一套适合中文校招的可编辑 A4 简洁版式。
- 支持现有标准模块、模块顺序、显示/隐藏、中文姓名、链接、头像及作品图；选用受控字体和段落样式。
- 导出前展示版式说明：网页模板较多，首版 DOCX 统一映射到这套 Word 版式，不承诺逐一复刻全部网页模板。
- 导出内容严格绑定当前选择的简历及版本；未保存草稿明确标识，实际投递留档仍选择已保存版本。
- Word、PDF、HTML、JSON 的导出入口都展示使用的简历名称与版本，避免投错材料。

### 投递前检查

| 编号 | 检查类型 | 输出与处理 |
| --- | --- | --- |
| C-01 | 完整性 | 缺失姓名/联系渠道、可见空模块、明显占位文字、空白经历标题；逐项跳转到编辑位置 |
| C-02 | 一致性 | 起止日期颠倒、同一经历中的日期矛盾、格式异常；跨经历时间重叠仅提醒核对，不自动认定错误 |
| C-03 | 文件预检 | 提示预览中的内容溢出、空白页、异常分页和不可见文字；区分“当前预览已检查”与“最终文件尚未检查” |
| C-04 | 最终 PDF 核对 | 提供回传浏览器打印 PDF 的检查入口，核对文本可提取性、关键字段和页数；未选择最终文件时不宣称检查过该文件 |
| C-05 | 岗位相关表达 | 复用当前岗位评估，将已确认但未在此简历表达的经历列为建议；无证据的能力列为待补充，不自动添加 |
| C-06 | 问题处理 | 标明错误、需核实和建议；用户可逐项修改或说明忽略，重新检查后更新结果 |

检查结果绑定简历版本、检查规则版本，以及使用时的目标岗位/评估版本。简历或目标岗位发生变化后，旧检查显示“需重新检查”。检查帮助发现具体问题，不输出没有依据的招聘系统通过率。

### 验收标准

1. DOCX 在实际可用的 Microsoft Word 与 WPS 中检查打开、编辑、中文、链接、图片和分页；未安装的客户端明确列为待验证。
2. 至少覆盖一页、跨页、长中文段落、中英文混排、隐藏模块、头像及作品图等样例，保留导出文件和检查记录。
3. 人工植入缺失联系方式、占位内容、反向日期与溢出等问题，检查能够定位；正常经历重叠不会被强判为错误。
4. 修改简历后旧检查失效；选择其他岗位不会沿用原岗位的表达建议。
5. 最终 PDF 的文字抽取检查与视觉检查分别记录；文字可抽取不等于排版已正确。

迁移要求：

1. 新增实体优先独立表管理。公共岗位与私人岗位必须有受约束的明确关联，不采用任意字符串替代全部引用完整性。
2. 旧投递、评估、材料、待办、简历版本与独立快照迁移后仍可读取。不能仅修改 `applications.job_id` 而遗漏评估和快照校验。
3. 新增个人实体进入个人数据导出，提升格式版本并说明兼容范围；不混入其他账号或服务商密钥。
4. 迁移先在数据库副本上验收，实施前备份完整本机数据；回退保留升级后新增数据，不直接用旧备份覆盖唯一数据库。
5. 新增后台刷新和提醒记录采用可恢复、可去重的执行方式，保持本机部署简单，不以引入复杂服务作为本轮前提。

## 10. 最终验收场景与交付清单

### 四条端到端场景

1. **外部岗位求职**：粘贴私人 JD → 确认与查重 → 评估 → 准备材料 → 绑定简历 → 保存实际投递快照。
2. **招聘过程推进**：粘贴二面通知 → 确认时间 → 发现冲突 → 改期 → 导出日历 → 收到提醒 → 记录结果与结束原因。
3. **机会订阅**：保存筛选/关注企业 → 成功刷新来源 → 发现新增岗位 → 收藏 → 后续要求或截止时间变化 → 查看差异和提醒。
4. **已有简历迁入**：导入 PDF/DOCX → 核对 → 保存新简历 → 预览进入底稿 → 针对岗位检查 → 修改 → 导出 Word/PDF → 用已保存版本留档。

- [ ] M3 首批来源刷新、订阅与变更消息。
